# Контроль якості · startup-edvault

Робота над цим репозиторієм вважається завершеною, лише коли пройдено кроки нижче. Це статична гра на чистому JavaScript
(ES-модулі, без збирання); стан гри лежить у `localStorage` і у файлі `.edvault`. Мова інтерфейсу українська, без емодзі,
звернення «ви» без роду, лише світла тема (правила з `CLAUDE.md` про темний режим тут не застосовуються).

## 1. Перед змінами
- Прочитай `CLAUDE.md` і `docs/audit-2026-11.md` (відомі проблеми й пріоритети, не відкривай їх заново).
- Для рішень про вигляд використовуй навички `frontend-design` і `ui-ux-pro-max` (якщо підключені) та `web-interface-review`
  (цей репозиторій). Стиль гри: товсті обводки кольору `--ink`, жорстка тінь `0 3px 0 var(--ink)`, жовті нотатки, шрифти Rubik/Golos.
- Кольори, радіуси, відступи, `z-index` беруться зі змінних `:root` (`app.css`); нові жорстко прописані значення не додавай.
- Перед новим класом CSS пошукай його назву (`grep`): старі стилі вже ламали нові блоки (`.qs`, `.cv-b`, `.ph`, `.top`).

## 2. Правила коду (обов'язково)
- Кожен рядок користувача чи зі збереження в HTML-шаблоні проходить `esc()`; нічого з імпортованого файлу не вставляй у `innerHTML` сирим.
- Збережений стан не вважай коректним: нові поля читай із запасним значенням (`d.x ?? ...`), масиви перевіряй `Array.isArray`.
- Помилка відмальовування однієї вправи не має класти всю сторінку.
- Новий інтерактив: `<button>`, видимий `:focus-visible`, підпис або `aria-label`, цілі натискання ≥ 44 px (на ПК допускається 32).
- Анімація лише `transform`/`opacity`, поважай `prefers-reduced-motion`.
- Тексти: одне слово для одного поняття (вправа, етап, розділ), дія на кнопці називається прямо, помилка пояснює, що робити далі.

## 3. Перевірки (запускай через `npm run …`, Playwright береться з `PLAYWRIGHT_MODULE`)
| Команда | Що перевіряє | Умова проходження |
|---|---|---|
| `npm test` | модульні тести | 0 помилок |
| `npm run test:e2e` | браузерні тести (ігровий процес, етапи, викладач, перенесення збереження) | усі файли пройшли |
| `node tests/startup-full-e2e.mjs homework` | повний прогін 104 тижнів і всіх вправ | 0 помилок, 0 проблем у звіті |
| `npm run audit:xss` | шкідливий текст у збереженні не виконується (гра й сторінка викладача) | 0 спрацювань |
| `npm run audit:fuzz` | пошкоджене збереження не ламає відмальовування | 0 падінь |
| `npm run audit:a11y` | axe-core WCAG 2.1 A/AA | 0 critical і serious |
| `npm run audit:keyboard` | фокус, пастка фокусу, Esc, масштаб 200 % | без зауважень |
| `npm run audit:perf` | швидкодія й бюджети | у межах бюджету |

Бюджети (`audit:perf`): екран малюється ≤ 150 мс, DOMContentLoaded ≤ 1500 мс (локально), збереження ≤ 600 КБ, тиждень гри ≤ 50 мс.

## 4. Візуальна перевірка
Зроби знімки 1366 і 390 пікселів завширшки змінених екранів (Playwright, `deviceScaleFactor: 1`), подивись очима й перевір, що нічого не вилазить
за межі (немає горизонтальної прокрутки). Для ПК якість важливіша за мобільну, але мобільна має лишатися робочою.

## 5. Звіт
Коротко українською: що змінено, що перевірено (з числами), чого не перевірено (живий сайт, реальні пристрої, скринрідери).
Не називай роботу завершеною, якщо `audit:*` падають через твої зміни. Відомі проблеми з `docs/audit-2026-11.md` можна лишати, доки їх не взято в роботу.

## 6. Пуш
Тести й перевірки пройдено → коміт із поясненням «що й чому» → пуш у `main`. Підпис у комітах і заборона на згадку моделі: як у системних правилах сесії.
